### 3. Platform recipe / admitted deviation

Profiles, platform CSS, split-document decisions, plate admissions, and asset substitutions record how one reading system preserves a relation.

A platform intervention must remain:

- explicit;
- bounded;
- traceable;
- reason-classed;
- removable when future evidence makes it unnecessary.

### 4. Frozen retailer derivative

Frozen Apple and Kindle EPUBs prove accepted package outcomes.

They do not replace the semantic source merely because they passed.

### 5. Retailer ingestion evidence

KDP or Apple Books upload, conversion, store preview, publication status, and post-publication smoke tests remain later operational evidence.

Retailer acceptance does not retroactively change source authority.

## 4. Source / evidence distinctions

- **Semantic source**: owns what the book says and what relations mean.
- **Retail master / common ancestor**: exact shared publication evidence before platform divergence.
- **Profile**: explicit transformation instructions tied to exact input identities.
- **Render-only CSS**: derivative presentation treatment; does not rewrite source wording.
- **Plate**: admitted platform representation of a bounded spatial relation.
- **Platform package**: retailer-specific assembly with explicit deviations.
- **Screenshot / reader pass**: renderer evidence.
- **EPUBCheck / Ace**: automated evidence with bounded claims.
- **Human acceptance**: separate judgment.
- **Retailer acceptance**: separate operational crossing.

No one evidence type silently upgrades another.

## 5. Rights boundary

The final retailer derivatives carry harmonized reader-facing rights language.

Operational source licensing remains limited to the exact identified files and material expressly marked for reuse.

Book prose, artwork, design, branding, and unmarked material remain reserved unless separately identified.

This tool does not invent, broaden, narrow, or republish license scope.

---

## 6. Mutation rule

An accepted source or frozen release is immutable by identity.

Any later change requires:

- a new source state where source changed;
- a new candidate where the package changed;
- fresh validation;
- fresh human acceptance;
- a new release identity.

Filename continuity is not byte continuity.

---

## 7. Repository purpose

This repository may:

- inspect exact EPUBs;
- verify package and source invariants;
- create bounded adaptation probes;
- record explicit admissions;
- audit final publication structure;
- preserve exact identities and method.

This repository does not:

- replace the upstream source repository;
- become a duplicate retailer-binary vault;
- infer human acceptance;
- infer accessibility certification;
- publish to KDP or Apple Books;
- alter frozen files in place.
