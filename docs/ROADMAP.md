# Roadmap after MFL Kindle Visual Adapter 0.14

## Completed foundation

The repository now contains:

- immutable input/hash custody;
- bounded component routing;
- device-reserve and vertical-footprint planning;
- deterministic raster packaging;
- human-governed optimization and admission;
- EPUBCheck and Ace orchestration;
- reproducibility evidence;
- explicit component versus whole-publication boundaries;
- complete Apple/Kindle BHT release evidence;
- a policy-aware whole-publication auditor.

BHT Apple EPUB 1 Release 001 and Kindle EPUB 1 Release 001 are frozen.

They are evidence sources, not future manuscript authority.

---

## Near-term work

1. Use the publication auditor against exact frozen Apple and Kindle releases on the Windows repository surface.
2. Preserve the resulting audit reports with the local release records.
3. Add future whole-publication policies only from exact accepted identities.
4. Keep Playbook 001 as lineage and Playbook 002 as current method.
5. Record retailer ingestion and post-publication smoke checks outside the frozen EPUB.
6. Update the public BHT source index to the accepted successor identities if that administrative task remains open.
7. Hand any future GitHub transport to the appointed GitHub mechanic with exact local commit/tag custody.

---

## Generalization work

For the next book:

1. establish semantic/source authority;
2. declare major semantic entries;
3. register meaningful graphics by relation;
4. build a shared package architecture;
5. derive narrow Apple/non-Kindle and Kindle platform layers;
6. use separate flow and graphic escalation branches;
7. record every platform deviation with a reason class and removal test;
8. prove source/content equivalence;
9. run whole-publication audit plus external validators;
10. perform native-renderer and whole-book human review;
11. freeze exact bytes;
12. treat retailer ingestion as a separate crossing.

---

## Candidate future engineering

- a reusable graphic registry schema and command-line validator;
- automatic generation of platform-deviation registers from policy records;
- richer navigation policy checks for internal destinations;
- optional comparison of sibling editions by semantic entry rather than by package member;
- machine-readable human-review receipt schemas;
- post-publication retailer smoke-check records;
- a controlled removal-test harness for historical renderer workarounds.

---

## Explicitly not planned

- automatic aesthetic classification;
- automatic candidate promotion or admission;
- one mandatory Apple/Kindle physical skeleton;
- treating plates as universally preferable to live graphics;
- treating a successful retailer EPUB as the next source;
- automatic KDP/Apple upload;
- accessibility certification inferred from Ace;
- human acceptance inferred from standards validation.

---

## Standing principle

BHT's classes, splits, plates, and CSS are training evidence.

They are not universal defaults.

The reusable method is:

> make the semantic anatomy explicit, then give each renderer only as much additional structure as it has earned.
